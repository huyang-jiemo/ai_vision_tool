# 众源感知解译工具技术设计

| 项目 | 内容 |
| --- | --- |
| 文档名称 | 众源感知解译工具技术设计 |
| 对应版本 | v0.5.4 |
| 适用产品 | 众源感知解译工具（AIVisionTool） |
| 文档性质 | 技术设计说明，供技术评审与维护参考 |

## 一、设计目标与原则

### 1.1 设计目标

在测绘数据保密约束下，实现车载全景影像与无人机正射影像的本地自动解译，输出与既有 GIS 体系直接衔接的矢量成果，并提供与存量地图的要素级变化比对。

### 1.2 设计原则

| 原则 | 落实方式 |
| --- | --- |
| 数据不出内网 | 检测模型本地推理，全流程无网络请求，无外部服务依赖 |
| 零安装 | PyInstaller 打包为独立目录，Python 运行时与全部二进制依赖随包分发 |
| 口径一致 | 成果坐标系取自存量参考文件；提取规则固化于代码，不依赖人工经验 |
| 异常隔离 | 单幅影像、单个导出格式的异常不影响整体任务，异常信息逐条落盘 |
| 双平台一致 | Windows 与 macOS 共用同一套界面与流水线代码，构建由 CI 统一产出 |

## 二、总体架构

系统为单进程桌面应用，分为界面层、桥接层与解译引擎三层。

```
┌──────────────────────────────────────────────────────┐
│                界面层（HTML/CSS/JS）                  │
│   车载影像提取 │ 正射影像提取 │ 变化比对               │
│   进度队列     │ 运行日志     │ 统计结果/预览          │
└────────────────────────┬─────────────────────────────┘
                         │ pywebview JS Bridge（本地 API）
┌────────────────────────▼─────────────────────────────┐
│                桥接层（api.py）                       │
│   任务启停 │ 状态轮询 │ 目录选择 │ 预览图 base64 通道  │
└────────────────────────┬─────────────────────────────┘
┌────────────────────────▼─────────────────────────────┐
│                解译引擎（pipeline/）                  │
│                                                      │
│  车载流水线：                                         │
│    data_loader → undistort → detector / lane_detector │
│      → georeference → change_detector → exporter     │
│                                                      │
│  正射流水线：                                         │
│    分块读取 → 分割 → 路面掩膜 → 走廊约束              │
│      → 矢量化 → 共线合并 → GDB 导出 → 预览渲染        │
│                                                      │
│  比对引擎：comparator（线/面/点三类匹配）              │
└──────────────────────────────────────────────────────┘
```

### 2.1 界面层

基于 pywebview 加载本地 HTML 页面（系统原生 WebView，macOS 为 WKWebView，Windows 为 WebView2），界面资源随包分发。界面代码位于 `web/`，单文件预览副本由 `tools/build_preview.py` 生成。

- 界面以设计令牌（tokens.css）统一色彩、字号与间距体系，三个工作台共用一套组件样式（components.css）；
- 页面按整屏布局设计，列表、表格与日志在卡片内部独立滚动，常规窗口尺寸下无整页滚动。
- 窗口关闭由平台原生确认框拦截（macOS 为 NSAlert、Windows 为系统消息框），文案本地化为中文并提示「退出将中断正在运行的任务」，避免误触关闭造成任务中断。

### 2.2 桥接层

`api.py` 通过 pywebview 的 JS Bridge 暴露本地 API，主要接口如下：

| 接口 | 职责 |
| --- | --- |
| start_pipeline / get_status | 启动车载解译任务；轮询任务状态（进度、当前文件、逐文件明细、日志、结果） |
| start_dom / get_dom_status | 启动正射提取任务；轮询状态与阶段提示 |
| start_compare / get_cmp_status | 启动变化比对；轮询比对结果 |
| scan_directory | 扫描数据源目录，报告可配对影像数量 |
| preview_image | 以 base64 通道返回结果预览图，规避 WebView 对本地中文路径 file:// 协议的限制 |
| pick_folder / pick_file / open_folder | 系统目录/文件选择对话框与打开目录 |

任务状态由 `RunState` 对象承载（加锁保护），包含 state、progress、total、current、files、logs、result、error 字段；每类任务（车载/正射/比对）各持有独立状态实例。任务线程同时通过 `_open_job_log` 在输出目录建立落盘日志文件，界面日志与文件日志同源。

### 2.3 解译引擎

引擎模块与职责：

| 模块 | 职责 |
| --- | --- |
| data_loader.py | 数据源扫描、.hdi 位姿解析、影像—位姿按批次与时间戳配对 |
| undistort.py | 鱼眼畸变校正，球面投影映射表构建与缓存 |
| detector.py | YOLO11 ONNX 推理封装，后处理（置信度过滤、手写 NMS）、业务类别归并 |
| lane_detector.py | 车道线提取（多重约束流水线） |
| georeference.py | 位姿 + 相机模型联合解算，像素坐标反投至地面 |
| change_detector.py | 车载成果多批次时序变化对比 |
| exporter.py | SHP / File GDB 矢量导出与投影文件生成 |
| processor.py | 车载任务调度与进度回调 |
| dom_extractor.py | 正射影像分块读取、标线分割、矢量化、共线合并、GDB 导出 |
| comparator.py | 要素级变化比对（线/面/点匹配策略） |
| imgio.py | 图像文件 Unicode 安全读写，屏蔽跨平台路径编码差异 |
| config.py | 参数与类别口径定义 |

## 三、关键算法设计

### 3.1 目标检测

- 模型：YOLO11n，动态尺寸导出，推理输入 1536（常规 640 的 2.4 倍），提升信号灯、标志牌、行人等小目标召回；单幅 CPU 推理约 0.16 秒；
- 运行时：ONNX Runtime CPU EP，避免引入 CUDA 依赖；
- 后处理：置信度阈值（默认 0.15，可配）过滤与 NMS 由代码实现，不依赖训练框架；
- 类别归并：模型输出按业务口径归并为动态障碍、交通标志、信号灯、路侧设施四大类。

### 3.2 鱼眼畸变校正

采用球面投影模型，使用相机内参（fx/fy/cx/cy）与畸变系数（k1/k2）构建像素级校正映射表并缓存；逐幅影像按映射重采样输出接近针孔成像的纠正影像，供检测与地理参考共用。

### 3.3 车道线提取

流水线由五重约束串联，逐级剔除非标线响应：

1. HSV 白/黄标线颜色掩膜与 Canny 边缘门控相交，抑制天空与大面积亮区；
2. Hough 直线段逐段沿线采样做颜色占比评分（阈值 55%），排除护栏、车顶支架等灰亮结构；
3. 剔除本车平台遮挡区（画面底部中央）；
4. 分左右侧 RANSAC 直线拟合（每侧至多 2 条），要求满足向消失点收拢的方向约束与消失点位置约束；
5. 采样点仅取有观测证据的区间，不向遮挡区域外推。

### 3.4 地理参考

利用 .hdi 位姿提供的位置与姿态，结合相机模型将像素坐标反投至地面，得到米制投影坐标，同时计算目标离车水平距离。投影定义直接取自参考成果 `.prj`，保证成果与既有底图坐标一致。

### 3.5 正射影像标线提取

面向单幅可达 5 万×8 万像素的大幅面 DOM 设计，处理流程如下：

| 阶段 | 设计要点 |
| --- | --- |
| 分块读取 | 2048 像素分块、256 像素重叠；重叠带要素按质心去重，避免边界重复 |
| 局部对比度分割 | 标线灰度减去周边中值抑制大块白色屋顶；低饱和度约束取白色标线，HSV 色域取黄色标线 |
| 路面掩膜 | 灰调、低饱和、低纹理连通域提取路面区域，仅保留路面内要素 |
| 走廊约束 | 以存量线状道路要素（LTSL 交通标线 / LFCL 附属设施线）缓冲 ±8 m 构建走廊，走廊外一律剔除 |
| 矢量化 | 最小外接矩形按长短轴分类：长宽比 ≥ 3 为线状，否则为面状 |
| 共线合并 | 端点网格索引（3×3 邻域检索）贪心合并共线碎片，配合方向一致性校验（夹角余弦 ≥ 0.95）；将全量两两比对优化为近线性复杂度，支撑万级要素规模 |
| 坐标统一 | DOM（EPSG:3857）与存量成果（武汉本地 TM）经 proj4 参数互转，输出坐标系与存量一致 |
| 尾段反馈 | 共线合并、GDB 写出、预览渲染三阶段计入进度刻度并输出日志，消除长耗时阶段的无反馈窗口 |

### 3.6 要素级变化比对

比对按几何类型自动配对图层（线↔线、面↔面、点↔点），匹配规则：

| 要素类型 | 匹配规则 |
| --- | --- |
| 线（标线） | 以存量为中心的覆盖式匹配：存量线被新线缓冲重叠覆盖 ≥ 50% 判匹配；方向按最近点局部切向校验，兼容长折线；无覆盖且 3 m 内存在平行新线判疑似改动，否则判缺失；未被覆盖的新线判疑似新增 |
| 面（面状标线） | 以新面被存量面覆盖比例为主，IoU ≥ 0.5 或覆盖 ≥ 80% 判匹配，兼容斑马线整体与单条条纹的粒度差异 |
| 点（标志设施） | 3 m 内最近邻一对一贪心匹配；新成果无该类要素时自动跳过，不误报缺失 |

变化要素按「chg_类型_几何」分图层组织，附 SRC（来源图层）与 NOTE（判定原因）字段，便于人工复核。

## 四、数据格式与接口约定

| 数据 | 格式 | 说明 |
| --- | --- | --- |
| 车载位姿 | .hdi（21 列文本） | 列定义经真实数据反查确认 |
| 正射影像 | GeoTIFF / BigTIFF | 含地理参考，EPSG:3857 或等效投影 |
| 存量成果 | File GDB | LTSL/LFCL 等图层，武汉本地 TM 投影 |
| 车载矢量成果 | SHP（pyshp 写出，附 .prj） | 纯 Python 实现，无外部二进制依赖 |
| 正射/比对成果 | File GDB（pyogrio OpenFileGDB 驱动写出） | ArcGIS 与 QGIS 可直接读取 |
| 比对报告 | JSON | 机读格式，含总量与分类明细 |

## 五、可靠性与质量保障

### 5.1 异常隔离

- 单幅影像处理异常不中断任务，失败文件在队列与日志中标记，任务结束统一汇总；
- SHP 与 GDB 导出相互独立，任一格式异常不影响另一格式与主流程；
- 比对中某类要素在新成果缺失时自动跳过，避免结构性误报。

### 5.2 文件路径与编码兼容

Windows 本地路径由系统按 ANSI 代码页（简体中文环境为 GBK）编码，而 OpenCV 的图像写入接口沿用 C 标准库以窄字符打开文件，遇到含中文的目录名或文件名时，会写出乱码文件名或直接写入失败。为此，全部图像落盘（车载逐幅标注预览图、正射叠加预览、比对预览）统一交由 `pipeline/imgio.py` 处理：先在内存中完成 PNG 编码，再以二进制方式写入目标路径，路径全程以 Unicode 传递。该处理使中文、空格及特殊字符路径在三类任务中表现一致，且不依赖系统区域设置；编码失败时抛出明确异常，由上层记入运行日志。

### 5.3 冻结包自检

打包产物内置四项自检（环境变量 `AVT_SELFTEST` 触发），发布前逐项执行：

| 自检项 | 验证内容 |
| --- | --- |
| gdb | File GDB 导出链路（pyogrio + gdal_data/proj_data 完整性） |
| rasterio | 正射影像读取链路（GDAL/PROJ 二进制依赖） |
| dom | 正射提取端到端分割（对给定 TIF 执行并校验掩膜像素数） |
| deps | pyproj/geopandas/pyogrio 导入与 EPSG:3857 坐标往返 |

### 5.4 打包与二进制兼容处理

macOS 平台存在 rasterio 与 pyproj 捆绑同名 `libproj` 动态库但二进制不兼容的问题（两者分别导出 GDAL 内部符号与 PROJ 公共符号）。构建脚本在 PyInstaller COLLECT 与 BUNDLE 两个阶段之后对落盘产物执行修正：顶层保留 rasterio 版本、pyproj 目录内恢复自身版本、并通过 `install_name_tool` 将 pyproj 扩展的库引用锁定至目录内副本，最后重新 ad-hoc 签名。该问题及修复由上述自检项覆盖。

### 5.5 持续集成

GitHub Actions 在 master 推送与版本标签（v*）推送时自动执行双平台构建：导出 ONNX 模型 → PyInstaller 打包 → 产物压缩 → 上传制品；版本标签构建额外创建 GitHub Release 并附 macOS（arm64）与 Windows（x64）安装包。

## 六、界面设计要点

- 单一主题色（#3E63D8）贯穿导航、按钮与进度条，进度条采用蓝→绿渐变表征任务推进；
- 三步操作指引（选择数据 → 选择输出 → 开始处理）随任务状态推进高亮；
- 文件队列支持状态筛选，处理中文件高亮标记；日志逐行带时间戳；
- 预览图组件内置滚轮缩放（1–10 倍，以光标为中心）、拖动平移与双击还原，缩放倍率受限防止过度放大失真；
- 结果区以轮询快照为唯一数据源：任务进入终态即停止轮询并整体重建结果区；预览图经 base64 通道异步返回，追加前校验本次渲染序号，过期结果直接丢弃，保证结果区始终只呈现一张预览图，不随时间累积；
- 卡片头（标题、路径、操作按钮）不参与压缩，路径超长按剩余空间省略，按钮不会被挤出卡片；
- 统计卡与进度卡采用等分四列网格，列宽随容器等比收缩；卡片内部允许换行，窄窗口下数值落到第二行，既不截断也不整排折行；
- 界面自动化回归基于 Playwright 无头浏览器执行，覆盖布局、状态流转与交互行为（见测试文档）。
