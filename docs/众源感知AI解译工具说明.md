# 众源感知 AI 解译工具说明

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 众源感知自动解译工具（AI Vision Tool） |
| 当前版本 | v0.2.5 |
| 运行平台 | Windows 10/11（x64）、macOS 12+（Apple Silicon） |
| 交付形式 | 免安装绿色包（zip 解压即用） |

---

## 一、需求背景

在城市基础设施巡检与地图更新业务中，巡检车辆沿途采集的海量街景照片与 GNSS/IMU 轨迹数据，长期依赖人工判读与手动矢量化的方式处理。该模式存在三方面突出问题：

1. **效率瓶颈**：单期数万张影像的人工判读耗时长，无法支撑高频次的地图更新与设施普查；
2. **标准不一**：不同作业员对目标取舍、地物归类理解不同，成果一致性难以保证；
3. **复用困难**：解译成果分散，缺少与既有 GIS 系统（ArcGIS/QGIS）直接衔接的数据格式。

为此，本项目研发一套**桌面端自动解译工具**，将巡检影像与轨迹位姿数据自动配对，完成目标检测、车道线提取、地理参考计算与矢量成果输出，形成可直接入库使用的 SHP / File GDB 成果，并支持多批次数据的时序变化对比。

## 二、需求分析

### 2.1 输入数据

| 数据 | 内容 | 说明 |
| --- | --- | --- |
| 照片/ | 全景相机按相机编号（CAM_x）组织的 JPG 影像 | 7360×4912 高分辨率 |
| 轨迹/ | 与影像同批次采集的位姿文件（.hdi 等） | 提供曝光瞬间的位置、姿态、高程 |

数据源目录要求：**照片/ 与 轨迹/ 按批次同名配对**（例如 `20260327_1-2（东湖路）/`），工具启动时自动扫描并报告可配对影像数量。

### 2.2 处理目标

| 目标类别 | 输出 |
| --- | --- |
| 车道线 | 左/右车道边界矢量线（含相邻车道线，每幅最多 4 条） |
| 交通标志 | 标志牌等面状目标（点要素 + 属性） |
| 信号灯 | 路口信号灯（点要素 + 属性） |
| 路侧设施 | 消防栓、停车计费器、路侧座椅等（点要素 + 属性） |
| 动态障碍 | 行人、非机动车、各类机动车（点要素 + 属性） |
| 时序变化 | 同一路段多批次采集间上述目标的出现/消失对比 |

### 2.3 输出成果

输出目录按三个子目录分区管理：

```
输出目录/
├── preview/   标注预览图（检测框与车道线叠加，供人工抽检）
├── shp/       Shapefile 矢量成果（目标点、车道线、时序变化）
├── gdb/       File GDB 地理数据库（与 SHP 同内容，供 ArcGIS 直接入库）
└── 解译日志_*.log  运行日志（参数、逐文件明细、异常、汇总）
```

| 成果 | 格式 | 说明 |
| --- | --- | --- |
| 目标点要素 | SHP / File GDB | 含类别、批次、来源影像、置信度、离车距离等属性 |
| 车道线要素 | SHP / File GDB | 点采样形式，含左右侧与所属批次 |
| 时序变化要素 | SHP / File GDB | 变化类型（新增/消失）、前后批次 |
| 标注预览图 | JPG | 检测框与车道线叠加可视化，便于人工抽检 |
| 运行日志 | 文本 | 按五大类别（动态障碍/交通标志/信号灯/路侧设施）分类统计 |
| 坐标系统 | 与参考成果一致 | 采用与轨迹参考 .prj 相同的投影定义，成果直接叠加既有底图 |

## 三、总体方案

工具采用**本地桌面应用**形态，全部计算在用户本机完成，数据不出内网，满足测绘数据保密要求。

```
┌────────────────────────────────────────────────────┐
│                桌面应用（pywebview）                 │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐  │
│  │ 解译配置  │  │ 解译进度  │  │ 运行日志/解译结果 │  │
│  └──────────┘  └──────────┘  └──────────────────┘  │
└───────────────────────┬────────────────────────────┘
                        │ 本地 API
┌───────────────────────▼────────────────────────────┐
│                   解译引擎（Python）                 │
│                                                    │
│  数据扫描与配对 → 鱼眼畸变校正 → 影像预处理           │
│      ↓                                             │
│  目标检测（YOLO11 神经网络，本地推理）                │
│  车道线提取（颜色掩膜 + 边缘门控 + RANSAC 拟合）      │
│      ↓                                             │
│  地理参考（位姿 + 相机模型 → 投影坐标）               │
│      ↓                                             │
│  矢量导出（SHP / File GDB） + 标注预览               │
│      ↓                                             │
│  多批次时序变化对比                                  │
└────────────────────────────────────────────────────┘
```

## 四、功能说明

### 4.1 解译配置

- **数据源目录 / 输出目录**：通过系统目录选择对话框选取，避免手工输错路径；
- **置信度阈值**：默认 0.15，可按场景在 0.05–0.90 间调节，阈值越低检出越多；
- **最大影像数**：用于小批量试跑验证（0 表示不限制）；
- **导出 SHP / 导出 GDB**：两种矢量格式可独立开关，默认全部导出；
- 鱼眼畸变校正默认启用，无需配置。

### 4.2 解译进度

- 整体进度百分比、已处理/总数、累计耗时实时刷新；
- **逐文件状态队列**：每幅影像实时显示"等待 / 处理中 / 完成 / 失败"及检出数量；
- 支持按"全部 / 成功 / 失败"筛选，便于失败重检。

### 4.3 运行日志与结果

- 运行日志实时输出逐文件解译明细与异常信息；
- 解译完成后展示各批次目标数 / 车道线数统计表；
- 一键打开输出目录查看成果。

## 五、技术实现

### 5.1 数据配对与解析

按目录约定扫描照片与轨迹文件，解析 .hdi 位姿（21 列定义已用真实数据反查确认），按批次与时间戳建立"影像—位姿"一一对应关系；无法配对的影像在日志中提示。

### 5.2 鱼眼畸变校正

针对全景相机的广角畸变，采用球面投影模型（内参 fx/fy/cx/cy 与畸变系数 k1/k2）建立校正映射表并缓存，逐幅影像按映射重采样，得到接近针孔成像的纠正影像，供检测与地理参考共用。

### 5.3 目标检测

- 采用 **YOLO11n** 目标检测网络，ONNX Runtime CPU 推理，**无需 GPU、无需联网**；
- 输入尺寸 1536（动态尺寸导出），相比常规 640 大幅提升信号灯、标志牌、行人等目标的召回率；单幅 CPU 推理约 0.16 秒；
- 输出按业务口径归为五大类别：**动态障碍**（行人、非机动车、各类机动车）、**交通标志**、**信号灯**、**路侧设施**（消防栓、停车计费器、座椅等）；运行日志逐文件、逐类别统计；
- 置信度阈值与 NMS 阈值可配置，手写 NMS 后处理，不引入深度学习训练框架。

### 5.4 车道线提取

针对城市道路场景（遮挡多、标线磨损、光照复杂）设计了多重约束的提取流程：

1. HSV 颜色掩膜（白色/黄色标线）与 Canny 边缘门控相交，抑制天空、路面大面积亮区；
2. Hough 变换提取直线段，逐段沿线采样进行颜色占比评分（≥55%），排除护栏、车顶支架等灰亮结构；
3. 排除本车平台遮挡区（画面底部中央）；
4. 分左右侧 RANSAC 直线拟合（每侧最多 2 条），要求满足收敛方向（向消失点收拢）与消失点位置约束；
5. 采样点仅取有观测证据的区间，不向遮挡区域外推，保证矢量真实性。

### 5.5 地理参考

利用位姿文件提供的相机位置与姿态，结合相机模型将影像像素坐标反投至地面，得到投影坐标（米制），并计算目标离车的水平距离。坐标系定义直接取自参考成果 .prj，与既有底图、存量数据完全一致，成果可直接叠加使用。

### 5.6 矢量导出

- SHP：纯 Python 写出（pyshp），稳定无外部依赖，附带投影文件（.prj）；
- File GDB：经 OpenFileGDB 驱动写出，目标层 detections / lanes / changes，ArcGIS 与 QGIS 均可直接读取；
- 任一格式导出异常不影响另一格式与主流程，异常信息记入运行日志。

### 5.7 时序变化对比

对同一路段不同批次的目标检测结果按空间位置与类别进行匹配，输出"新增 / 消失"变化点，服务于设施增减普查与地图更新。

### 5.8 工程与发布

- 桌面壳层基于 pywebview（系统原生 WebView），界面零依赖、启动快；
- PyInstaller 打包为免安装目录，Windows / macOS 双平台由 CI 自动构建并发布；
- 内置自动更新版本的版本号标识，问题反馈可直接对应版本定位。

## 六、实施过程

项目按以下阶段推进，每阶段均以真实数据验证后进入下一阶段：

| 阶段 | 内容 | 验证方式 |
| --- | --- | --- |
| 一、数据摸底 | 解析测试数据组织结构、位姿格式、参考成果坐标系 | 用参考矢量反查字段与坐标定义 |
| 二、单点技术攻关 | 影像—位姿配对、鱼眼校正、地理参考精度 | 投影坐标与参考成果叠合检查 |
| 三、检测与车道线 | 神经网络检测集成、车道线多重约束算法 | 真实影像逐类检出率对比、预览人工核验 |
| 四、成果输出 | SHP/GDB 导出、坐标系一致性、时序变化 | ArcGIS/QGIS 读取验证、与底图叠合 |
| 五、产品化 | 桌面界面、进度可视化、异常提示、双平台打包 | 全流程真实数据回归 + 双平台安装验证 |

## 七、部署与使用

1. 解压对应平台的 zip 包（Windows x64 / macOS Apple Silicon）；
2. Windows 双击 `AI-Vision-Tool.exe`；macOS 双击 `AI-Vision-Tool.app`（首次打开若提示安全确认，请右键选择"打开"）；
3. 选择数据源目录（含按批次配对的 照片/ 与 轨迹/）与输出目录，点击"开始解译"；
4. 解译完成后在输出目录获取成果：`preview/` 标注预览、`shp/` 矢量、`gdb/` 地理数据库、`解译日志_*.log` 运行日志。

**性能参考**（Apple M4 / 现代多核 CPU 量级）：单幅影像端到端约 0.5–1 秒；148 幅测试数据全流程数分钟内完成。

## 八、已知边界与后续规划

**当前边界**

- 检测模型采用通用预训练权重，对特定区域特有标志牌、异形设施等目标召回有限；
- 车道线提取面向结构化城市道路设计，无标线路段或严重遮挡路段可能少检/不检；
- 鱼眼校正参数为相机初值，边缘区域存在残余畸变，远景地物定位精度有限。

**后续规划**

1. 使用业务采集数据对检测模型进行微调，提升标志牌、路侧设施等类别召回与定位精度；
2. 支持更多相机机型与畸变模型自标定；
3. 增加正射影像叠加质检与更多要素类别（护栏、井盖、标线破损等）；
4. 提供批量任务队列与成果质量报告。
